# Сервер аккаунтов (Cloudflare Workers + D1)

Хранит игроков и их прогресс, чтобы он не пропадал вместе с браузером и переезжал между устройствами.
Сайт остаётся на GitHub Pages, сюда он ходит только за прогрессом.

Бесплатного тарифа хватает с запасом: 100 000 запросов в день, база D1 — 5 ГБ.
Один игрок за час игры делает десятки запросов, не тысячи (прогресс уезжает не чаще раза в 4 секунды).

## Файлы

| Файл | Зачем |
|---|---|
| `worker.js` | сам обработчик (регистрация, вход, прогресс) |
| `lib.js` | проверки, пароли, токены — отдельно, чтобы покрыть тестами |
| `worker.bundled.js` | **то, что вставляется в Cloudflare**: `worker.js` + `lib.js` одним файлом |
| `schema.sql` | таблицы базы |
| `dev-server.js` | тот же обработчик локально, поверх SQLite — для разработки |
| `tools/bundle.js` | пересборка `worker.bundled.js` |

После правок в `worker.js` или `lib.js` — `node server/tools/bundle.js`, иначе тест упадёт,
а в Cloudflare останется старый код.

## Выкладывание через панель (без установки программ)

1. **Регистрация.** [dash.cloudflare.com](https://dash.cloudflare.com) — почта и пароль, карта не нужна.

2. **База.** Слева **Storage & Databases → D1 SQL Database → Create database**.
   Имя: `tggames`. Создать.
   Внутри базы — вкладка **Console**: вставить целиком содержимое `schema.sql` и выполнить.
   Консоль склеивает вставленное в одну строку, поэтому в `schema.sql` только блочные комментарии
   `/* */`; однострочные `--` съели бы всё остальное («Requests without any query are not supported»).
   Проверка: вкладка **Tables** — должны появиться `users`, `sessions`, `states`, `attempts`.

3. **Обработчик.** Слева **Compute (Workers) → Create → Start with Hello World → Deploy**.
   Имя: `tggames-api`. После создания — **Edit code**: удалить всё, что там есть, и вставить
   содержимое `worker.bundled.js`. **Deploy**.

4. **Связать обработчик с базой.** В настройках обработчика: **Settings → Bindings → Add → D1 database**.
   - Variable name: `DB` (ровно так, обработчик ищет именно это имя);
   - D1 database: `tggames`.
   Сохранить и **Deploy** ещё раз.

5. **Адрес.** На странице обработчика он вида `https://tggames-api.ИМЯ.workers.dev`.
   Проверка: открыть его в браузере — должно ответить `{"ok":true,"service":"tggames"}`.

6. **Вписать адрес в сайт.** В `shell/config.js`:
   ```js
   export const API_URL = 'https://tggames-api.ИМЯ.workers.dev';
   ```
   Закоммитить и запушить. Пока там пусто — сайт работает без аккаунтов, прогресс живёт в браузере.

## Кто может обращаться

В `worker.js` — список `ALLOWED_ORIGINS`: сайт на GitHub Pages и локальные адреса разработки.
Чужой сайт обратиться к обработчику от имени игрока не сможет. При смене домена список правится,
файл пересобирается и заливается заново.

## Как проверить локально, ничего не выкладывая

```
node server/dev-server.js 8787      # сервер аккаунтов на SQLite (база server/dev.sqlite)
npm start                           # сайт на 8000
```
и временно в `shell/config.js`: `export const API_URL = 'http://127.0.0.1:8787';`

## Что хранится

- `users` — имя и хэш пароля (PBKDF2-SHA256, 120 000 итераций, своя соль у каждого). Самого пароля нет.
- `sessions` — хэш токена, срок полгода. Утечка базы не даёт войти в аккаунт.
- `states` — весь прогресс игрока одной строкой JSON (до 400 КБ) и отметка времени.
- `attempts` — неудачные входы: 10 подряд за 15 минут блокируют имя.

Почта не спрашивается, поэтому **забытый пароль восстановить нельзя** — об этом написано на экране входа.
