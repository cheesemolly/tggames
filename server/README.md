# Сервер (Cloudflare Workers + D1): вход через Telegram, прогресс, панель, бот

Один воркер делает три вещи: узнаёт игрока по подписи Telegram, хранит его прогресс и отвечает
в чате как бот. Сайт остаётся на GitHub Pages, отдельного хостинга не нужно.

Бесплатного тарифа хватает с запасом: 100 000 запросов в день, база D1 — 5 ГБ.

## Файлы

| Файл | Зачем |
|---|---|
| `worker.js` | обработчик: вход, прогресс, панель владельца, вебхук бота |
| `lib.js` | проверка подписи initData, разбор данных — отдельно, чтобы покрыть тестами |
| `worker.bundled.js` | **то, что вставляется в Cloudflare**: `worker.js` + `lib.js` одним файлом |
| `schema.sql` | таблицы базы |
| `dev-server.js` | тот же обработчик локально, поверх SQLite — для разработки |
| `tools/bundle.js` | пересборка `worker.bundled.js` |

После правок в `worker.js` или `lib.js` — `node server/tools/bundle.js`, иначе тест упадёт,
а в Cloudflare останется старый код.

## Как работает вход

Telegram кладёт в мини-приложение строку `initData`: кто открыл игру, когда — и подпись. Подпись
сделана ключом, выведенным из токена бота, поэтому подделать её на клиенте нельзя, а сервер может
проверить. Игра шлёт эту строку в заголовке `Authorization: tma <initData>`, сервер сверяет подпись,
находит игрока по `tg_id` (или заводит при первом заходе) и работает с его прогрессом.

Паролей, регистраций и сессий нет. Вне Telegram сервер не отвечает ничем полезным — сайт в браузере
играется как гостевой, прогресс живёт в самом браузере.

## Настройка (панель Cloudflare)

1. **Бот.** В [@BotFather](https://t.me/BotFather): `/newbot`, затем `Bot Settings → Menu Button` —
   URL мини-приложения `https://cheesemolly.github.io/tggames/`.

2. **База.** Слева **Storage & Databases → D1 → Create database**, имя `tggames`.
   Вкладка **Console**: вставить содержимое `schema.sql` и выполнить.
   Если база осталась от версии с паролями, сначала удалить старые таблицы — команды в шапке `schema.sql`.

3. **Обработчик.** **Compute (Workers) → Create → Hello World → Deploy**, имя `tggames-api`.
   Потом **Edit code**: стереть всё и вставить содержимое `worker.bundled.js`. **Deploy**.

4. **Привязка базы.** **Settings → Bindings → Add → D1 database**: Variable name `DB`, база `tggames`.

5. **Переменные.** **Settings → Variables and Secrets**:

   | Имя | Что это | Тип |
   |---|---|---|
   | `BOT_TOKEN` | токен от BotFather | Secret (зашифровать) |
   | `ADMIN_IDS` | Telegram-id владельца (несколько — через запятую) | Text |
   | `WEBHOOK_SECRET` | строка **только из латиницы, цифр, `_` и `-`** (1–256 символов), её же укажем при подключении вебхука | Secret |
   | `APP_URL` | адрес мини-приложения, если отличается от `https://cheesemolly.github.io/tggames/` | Text |

   Свой id можно узнать у [@userinfobot](https://t.me/userinfobot).
   После добавления переменных — **Deploy** ещё раз.

6. **Вебхук бота.** Открыть в браузере (подставив токен, адрес воркера и тот же секрет):

   ```
   https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://tggames-api.<ИМЯ>.workers.dev/bot&secret_token=<WEBHOOK_SECRET>
   ```

   Ответ `{"ok":true,...}` — готово. Проверка: написать боту `/start`, он ответит кнопкой «Играть».

   Если ответ `Bad Request: secret token contains illegal characters` — в секрете есть что-то, кроме
   латиницы, цифр, `_` и `-` (например кириллица или пробел). Поменять его нужно **в двух местах**:
   в переменной воркера (с повторным Deploy) и в этой ссылке — значения должны совпадать, иначе
   воркер будет отклонять вызовы Telegram и бот молча перестанет отвечать.

7. **Адрес в сайте.** В `shell/config.js` — адрес воркера, коммит и пуш.

## Что умеет бот

- `/start` — приветствие и кнопка, открывающая игры;
- `/me` — уровни и рекорды игрока текстом;
- инлайн-режим `@бот …` в любом чате — см. ниже;
- `/broadcast текст` — рассылка всем игрокам, **только для ADMIN_IDS**;
- `/message @ник текст` (или id вместо ника) — сообщение одному игроку от имени бота, **только для ADMIN_IDS**.
  Ник ищется среди тех, кто открывал игры.

К обеим командам можно прикрепить фото или видео (одно или альбом до 10) — команда пишется в подписи.
Бот сначала показывает владельцу, как это увидят («Так это увидят:»), и отправляет только по кнопке
«Разослать» / «Отправить»; «Отмена» — никому. Второе нажатие ничего не повторит. Текст и одно фото
уходят с кнопкой «Играть»; к альбому Telegram кнопку прикрепить не даёт. Подпись к фото — до 1024
символов, текст — до 4096. Таблицы черновиков (`drafts`, `draft_media`) обработчик заводит сам.

**Оформление сохраняется:** жирный, курсив, ссылки, цитата и сворачиваемая цитата, спойлер — всё, что
сделано в Telegram при наборе, уходит игрокам так же (разметка `entities` сдвигается на вырезанную команду
и ник). Столбец `entities` в `drafts` обработчик добавляет сам.

## Инлайн-режим: «@бот» в любом чате

В любом чате или личке набираешь имя бота — появляется список:
- пусто — «🎮 Позвать играть» (все игры одним сообщением), «🏆 Мои рекорды» (если уже играл) и каждая игра;
- `@бот судоку` (начало названия или любого его слова) — эта игра;
- `@бот рекорды` (или «мои», «прогресс») — свой прогресс, как в `/me`.

Под отправленным сообщением — кнопка-ссылка `t.me/<бот>?startapp=<игра>`: она открывает главное
мини-приложение сразу на этой игре (кнопки web_app Telegram в чужих чатах не разрешает). Поэтому нужно
включённое главное мини-приложение (раздел ниже, «Открыть»).

**Включить (один раз):** в @BotFather `/setinline` → выбрать бота → текст подсказки в поле ввода,
например `игра или «рекорды»`. После этого — заново вставить `worker.bundled.js` в Cloudflare
(там обработчик инлайн-запросов). Вебхук переставлять не нужно, если при `setWebhook` не задавался
`allowed_updates`. Имя бота обработчик узнаёт сам (`getMe`); можно задать переменной `BOT_USERNAME`.

## Кнопки запуска игр в Telegram (настраиваются в @BotFather, не в коде)

- **«Открыть» в списке чатов и в профиле бота** — главное мини-приложение:
  `/mybots` → бот → Bot Settings → Configure Mini App → Enable Mini App → адрес
  `https://cheesemolly.github.io/tggames/`. Надпись («Открыть» / «Open») задаёт сам Telegram.
- **«🎮 Играть» слева от скрепки в чате с ботом** — кнопка меню:
  `/mybots` → бот → Bot Settings → Menu Button → Configure menu button → тот же адрес → название `🎮 Играть`.

## Панель владельца

Открывается в самой игре: в меню появляется кнопка «Панель» — но только у тех, чей id есть в
`ADMIN_IDS`. Доступ закрывает сервер, а не интерфейс: без нужного id запросы `/admin/*` отвечают 403.

Внутри: список игроков с поиском по имени, @username и id; карточка игрока с правкой статистики
(сыграно / побед / рекорд), строк уровней и всего прогресса в виде JSON; блокировка и удаление;
рассылка.

Правки сохраняются с отметкой времени «из будущего» — так устройство игрока при следующем обмене
применит их, а не затрёт своим прогрессом.

## Как проверить локально, ничего не выкладывая

```
node server/dev-server.js 8787      # сервер на SQLite (база server/dev.sqlite)
npm start                           # сайт на 8000
```

Вход в браузере не заработает (нет подписи Telegram) — это ожидаемо; локально проверяется сам
обработчик, а его поведение целиком покрыто тестами `npm test`.

## Что хранится

- `users` — Telegram-id, имя и @username (обновляются при каждом заходе), даты, признак блокировки;
- `states` — весь прогресс игрока одной строкой JSON (до 400 КБ) и отметка времени.

Ни телефонов, ни паролей, ни переписки. Имя и username Telegram отдаёт сам при открытии мини-приложения.
